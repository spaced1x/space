# SPACE v1.0.0 — Release Gate

The gate is executed on the VPS, in production mode, immediately before the
version is promoted. It is generated by `generateReleaseReport("v1.0.0")`, which
writes a JSON snapshot into this directory and records the outcome in the
`release_artifacts` table. A single failed item blocks promotion.

## Automated checklist

| Item | Requirement |
| --- | --- |
| `env_valid` | Startup validation returns valid with no failed required item |
| `health_ok` | Overall health is OK or DISABLED |
| `db_ok` | Database component is OK (WAL, all migrations applied) |
| `scheduler_ok` | Scheduler component is OK, drift within tolerance |
| `no_emergency_stop` | The emergency-stop latch is clear |
| `not_armed` | The engine is not ARMED while the gate runs |
| `metrics_sampled` | At least one metrics sample exists |

## Environment conformance gate

All six items must pass before ARM is permitted:

1. V1 Testnet resolves to the staging CLOB host and chain 80002.
2. V2 Mainnet resolves to the production CLOB host and chain 137.
3. Switching `SPACE_ENVIRONMENT` yields the matching host and chain pair.
4. The live `eth_chainId` from `POLYGON_RPC_URL` matches the environment.
5. The configured wallet address matches the environment's expected deployment.
6. The database environment stamp equals the running environment.

## Manual sign-off

- [ ] Fresh clone on the VPS: install, build, PM2 start, health endpoint green
- [ ] Dashboard renders every workspace with zero console errors
- [ ] Telegram permission mode set deliberately for this host
- [ ] Backup schedule verified and one restore rehearsed
- [ ] Rollback procedure read by the operator on duty
- [ ] Operator confirms `.env` secrets belong to the intended environment

Promotion is authorised only when the automated checklist reports
`gate.passed = true` and every manual item is signed off.
